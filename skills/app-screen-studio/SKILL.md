# 画面編集室

このスキルと同じフォルダの `tool/studio.py` が実行ツール。スキルファイルの実際の場所から絶対パスを組み立てる。PC名・既定のインストール先・現在の作業フォルダを決め打ちしない。

## 起動と編集

1. 対象アプリの既存ソース・プレビュー方法・未保存入力を確認する。同じ作業セッション内でサーバーを実行し、他のアプリや既存サーバーを終了しない。
2. Python 3.10以上で `python <toolの絶対パス>/studio.py --project <名前> --dir <画面ソース> --entry /index.html --output-root <成果物ルート>` を実行する。起動したまま使い、終了はCtrl+C。開くURLは起動出力を読む。既存の開発サーバーは `--dir` の代わりに `--url http://127.0.0.1:<ポート>` を指定する。
3. 利用者が編集できるローカル画面を、そのセッションのプレビューまたは専用ブラウザーで開く。公開はしない。文字・色・フォント・配置、約0.5秒の長押し移動、画面外からの囲み選択、材質・最大4色グラデーション・文字発光を使える。
4. 利用者は編集を保存して「AIへ渡す指示をコピー」を押す。クリップボードと編集室下の指示欄へ反映される。既存文は保持し同一指示を重複追加しない。この操作でAIへ送信しない。
5. 共通の受渡しは「AI用ファイルを保存」。表示された依頼文Markdownを、呼出元AIのチャットで指定する。画像もファイルへ保存され、依頼文へパスが入る。AIは実ファイルを開いて確認する。別PC・リモート環境なら依頼文・JSON・画像を一緒に渡す必要がある。

## Orcaでの追加連携

Orca上では先に同梱の `tool/prepare_launch.py` を呼出元AI自身から実行する。引数は `--project <名前> --dir <画面ソース> --entry <画面パス> --port <空きポート>`。返された起動引数を同じワークスペースの可視ターミナルで実行し、接続確認OKと送信ボタン有効まで確認する。接続できなければ別のAIへ送らず、共通のファイル受渡しを使う。

Orcaの「AIへ送信」は送信登録までで、受領・製品コード反映とは別。編集画面内のスクショはOrca連携とPillowが必要。他環境では対象アプリ部分の画像を本人が撮り、画像添付または貼り付けで渡せる。

## 元ソースへの反映

依頼文・編集JSONを読み、対象要素の識別子と編集前の内容を現在のソースに照合する。変更を元のコンポーネントへ適用し、レスポンシブ表示・操作・アクセシビリティを保つ。一致しない要素は推測で書き換えない。保存JSONを受け取っただけで製品反映済みと報告しない。反映後は同じ画面幅で再表示する。

再読込前に未保存の編集・文章・添付を保護する。不要になった自作のタブとサーバーを閉じ、他者の作業を止めない。
